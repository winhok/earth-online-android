# 11: 交付逾期核对与批量天劫结算

**What to build:** 让应用在用户离线跨过截止日后准确、一次性结算全部失约，并以强烈但可理解的全屏仪式说明每笔损失，而不是依赖后台常驻或重复骚扰。

**Blocked by:** 10: 交付暂缓、改期、弃约与重新签约.

**Status:** ready-for-agent

- [ ] 截止边界为契约时区 `dueDay + 1` 的开始，时间戳使用 UTC。
- [ ] 启动、刷新及完成、编辑、暂缓、暂停、归档和撤销等权威写操作前执行一致的 reconcile 顺序。
- [ ] 应用关闭数日后，每份未履约契约只生成一次全额原始奖励代价。
- [ ] 多项同日逾期逐项完整结算，不设置每日扣罚上限。
- [ ] 契约、代价和审计在同一事务写入，失败时不暴露部分结果。
- [ ] 并发 reconcile 与用户命令依靠唯一键和数据库事务得到一个可解释结果。
- [ ] 一份契约产生完整逾期后，再暂停、归档或清除日期不会重复收取弃约代价。
- [ ] 每批新事件只展示一次全屏天劫结算；返回键不能绕过首次确认，但确认后不强迫进入恢复路线。
- [ ] 首屏展示总损失、当前等级影响和前三项依据，其余项目可展开。
- [ ] 结算完成后保留可重新进入的状态入口，不重复全屏打断。
- [ ] 地球原生与修仙显示不同叙事，但逐项数值、日期和契约 ID 对应一致。
