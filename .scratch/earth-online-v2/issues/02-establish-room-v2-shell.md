# 02: 建立 Room v2 兼容外壳

**What to build:** 让现有 1.0 用户升级后无损进入统一的 v2 数据外壳，为叙事选择、时限契约、代价账本、偿还分配和恢复状态提供完整持久化结构，同时保持当前可见行为不变。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] 数据库版本通过显式 Migration 从 v1 升至 v2，禁止 destructive fallback。
- [ ] v2 结构能保存稳定叙事体系 ID、体系展示偏好、时限契约及修订、代价事件、偿还分配、豁免／返还、时钟边界和恢复路线状态。
- [ ] 契约、代价和分配使用稳定 ID、外键和幂等约束，不能复用展示日志充当权威账本。
- [ ] 一次性任务仍以任务 ID 加 `once` 作为完成身份，日常完成身份保持存档日期语义。
- [ ] 现有玩家、主线、任务、完成和日志升级后逐项保持不变。
- [ ] 现有带日期的一次性任务和 Boss 迁移为“未签约”，不会生成追溯处罚。
- [ ] 现有玩家默认选择地球原生体系，原明暗主题设置保持不变。
- [ ] 从真实 v1 数据库夹具升级、关闭并重开后，所有旧数据和新增默认状态一致。
- [ ] 迁移中任一步失败时，旧数据库不被部分替换。
- [ ] Room schema 只能在真实 Android 构建成功后生成和纳入后续交付。
