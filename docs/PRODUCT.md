## Platform

android

## 事实来源

当前版本以仓库中的实际代码和可追溯验证证据为最终事实。本文档用于逐步沉淀长期产品上下文；若文档与当前实现冲突，应先核对代码和验证记录，再更新本文档。

## 一句话与边界

用户打开应用后，能够找到一件现在适合做的现实任务，完成后获得可回溯的成长记录。世界观服务于行动，不要求用户维护复杂数值，也不根据收入、年龄、外貌或健康给“战斗力”评分。

本版面向中文用户、Android 手机及基础大屏布局。无需登录、可离线运行。产品不使用持续打卡惩罚、生命值扣除、付费复活和成瘾性随机奖励。跳过或归档任务不代表失败。

## 第一次使用

进入创建角色页，填写玩家名与自定义服务器名，创建本机存档。服务器名只是昵称，不会连接真实服务器或请求位置。存档时区取创建角色时的设备时区并固定保存，不通过 IP 推断地区。

创建一项真实任务，选择类别、强度、技能、预计分钟数、优先级、日期及可选主线。默认无任务、无假 XP、无虚构成就。用户不创建任务时，首页保持可操作的空状态。

## 任务语义

| 概念 | 含义 | 结算 |
| --- | --- | --- |
| 主线 | 长期方向及完成标准，容纳若干任务 | 不直接发 XP；进度由关联任务推导 |
| 支线 | 一次性具体行动 | 生命周期一个奖励槽位 |
| 日常 | 每个自然日可进行一次的重复行动 | 存档时区每天一个奖励槽位；不补签 |
| Boss | 比较重要的一次性行动 | 一次奖励，强度 XP +25 |
| 暂缓 | 暂时移出推荐，不更改原截止日 | 不扣 XP，累计暂缓次数 |
| 暂停 / 归档 | 当前不行动 / 从活跃队列移除 | 保留完成历史和 XP |
| 重新接取 | 恢复活跃、清除暂缓和重审计数 | 不凭恢复动作再次奖励 |

简单、标准、挑战强度分别为 10、25、50 XP；Boss 分别为 35、50、75 XP。五项技能与全局等级均使用已生效的完成记录推导。技能值是应用内活动记录，不声称测量真实能力。

日常“日期”是开始日期；支线和 Boss“日期”是截止日期。过期不扣分，仍可完成。日常不会因为漏一天产生无限积压的历史待办。

## Next Quest

用户选可用时间与精力。系统先过滤暂停/归档、未开始的日常、暂缓中、当天已完成、超出时间或精力预算的任务，再计算推荐顺序：优先级、过期、今日到期、临近截止、关联活跃主线、日常。

推荐理由明确显示，不声称使用 AI 或读取用户手机行为。没有可推荐任务时，允许休息、调整预算或创建更小行动；不把没有任务视为错误。

## 重审而非惩罚

暂缓达到三次时进入“重审”。用户可以缩小任务描述、降低挑战强度、暂停、归档或重新接取。应用不擅自删除、自动完成或替用户改变截止日期。重审计数清零是显式操作，不伪造完成记录。

## 完成、撤销与成长

重复点击完成不重复发 XP。撤销针对确切完成 ID，即使消息栏跨过午夜也不会撤销另一日。撤销后重做保留原奖励与技能快照，避免修改强度后通过反复撤销获益；新的日常结算日使用当时的新配置。

连续行动天数允许今天尚未完成时展示截至昨天的连续记录。七项成就由有效完成记录计算，连续成就按历史最长连续记录计算，普通休息日不会抹去已达成的连续成就。显式撤销构成该成就的记录可能让成就不再满足，这与总经验回滚一致。

## 提醒与存档

提醒默认关闭，主动开启才申请系统通知权限。使用 WorkManager，每日设定小时之后有可行动任务时提醒；不保证准点、送达或后台常驻。通知显示可行动任务数量，不显示私人任务标题。

用户通过系统文件选择器导出明文 JSON，导入前校验格式、版本、大小、哈希、ID、外键、奖励与日期。显示预览并再次确认后在事务内覆盖，不自动合并。导入后提醒关闭。清空要求输入“删除”，不会触及用户已导出的外部文件。

## 已确认的后续方向（尚未实现）

地球 Online 的长期世界观是“唯一服、单向时间、现实结算”。底层保存中立的任务、主线、完成、经验、技能、截止日期、代价与恢复记录；地球原生、修仙、武侠等体系只是可切换的叙事解释器。用户可以不选择体系，也可以随时切换。切换只改变名称、图标、配色、触觉和结算演出，不迁移数据、不重算奖励，也不改变规则。

地球原生体系是默认表达；修仙体系作为第一套扩展，映射历练、仙途、渡劫、劫债、境界和堕仙重修等概念。堕仙不是永久人格判定，而是一条由失约触发、可以通过真实行动修回正途的成长主线。后续体系必须映射同一组稳定语义 ID，不能通过切换体系规避代价或取得额外奖励。

后续版本将把所有一次性任务和 Boss 的截止日期定义为明确的时限契约。逾期会产生一次、可追溯且可恢复的代价，创建和编辑时必须预先展示；不能按离线天数无限叠加，也不能依赖进程在午夜存活。结算使用玩家存档时区并保持幂等，代价与审计记录在同一事务内写入。日常任务的日期仍是开始日期，不因漏做产生历史债务。

以上是已确认的产品方向，不是 1.0 已实现能力。在相应的数据模型、迁移、界面、无障碍、撤销边界和测试全部完成前，当前版本仍按本文前述规则执行：过期不扣分，叙事体系不可切换。

## 本版明确不含

不含 AI 生成/拆解任务、云同步、账户登录、社交/公会、联网排行、金币商城、订阅支付、地图、DAG 依赖、番茄钟、桌面 Widget、周/月重复规则、历史日常补签和跨存档合并。不为这些能力放不可用的 UI 入口。

主线可以归档但尚无单独的主线恢复入口；任务可以从归档重新接取。若需要改变此产品行为，应补齐 UI、规则、数据与测试后发布，而不是仅改文案。

## 体验验收

发布前要求用户独立走通“创建角色 → 创建主线 → 创建关联任务 → 完成 → 查看成长 → 撤销 → 导出 → 删除 → 导入恢复”。检查大字体、无障碍、深色、横屏、键盘遮挡、返回放弃草稿和进程恢复。

本版无埋点 SDK。内测通过自愿反馈和设备端验收记录评估，不擅自采集任务文本、手记或备份文件。
